# proxprobe

Собирает прокси-подписки разных форматов, проверяет узлы живым запросом через
mihomo и выгружает результат в Clash YAML.

Один бинарник, никаких зависимостей кроме ядра mihomo (и то только для
команды `probe`).

## Что умеет

- **Читает** пять форматов: списки ссылок (`vless://`, `ss://`, `vmess://`,
  `trojan://`, `hysteria2://`), base64 от списка ссылок, Clash YAML, Xray-конфиги
  (одиночный и пачку по обёртке `data:`), sing-box JSON.
- **Не угадывает формат по URL** — определяет по содержимому. Это принципиально:
  один и тот же адрес отдаёт разное в зависимости от `User-Agent`.
- **Убирает дубликаты** между источниками: один и тот же узел, приехавший в
  vless-ссылке и в Clash YAML, схлопывается в один.
- **Проверяет** узлы TCP-диалом, затем — реальным HTTP-запросом через ядро
  (это ловит узлы, которые принимают соединение, но не пропускают трафик).
- **Выгружает** в `clash/merged.yaml` (все узлы) и `clash/sorted.yaml` (живые, по
  возрастанию задержки). Группы плоские: `PROXY` → `AUTO` и страны,
  страна → её узлы. Вложенных селекторов нет.
- **Экспорт — только Clash/mihomo.** Парсеры Xray и sing-box остались, потому
  что источники в этих форматах приходят, но на выходе их нет.

## Сборка

Нужен Go. CGO не нужен — наоборот, выключен:

```sh
CGO_ENABLED=0 go build ./cmd/proxprobe
```

В NixOS собирается из `pkgs/proxprobe/package.nix` в
[nixos-config](https://github.com/kyomufs/nixos-config); версия подставляется
линкером через `-X main.buildVersion`.

## Использование

```sh
proxprobe all                 # весь конвейер: fetch → parse → merge → ping → probe → export
proxprobe version
```

Отдельные шаги, если нужно посмотреть промежуточный результат:

```sh
proxprobe fetch               # скачать подписки в out/raw/
proxprobe parse               # разобрать в out/nodes/
proxprobe merge               # слить источники без дубликатов → out/probe/merged.jsonl
proxprobe ping                # TCP-проверка → out/probe/tcp.jsonl
proxprobe probe               # запрос через ядро → out/probe/http.jsonl
proxprobe export              # → out/clash/merged.yaml, out/clash/sorted.yaml
```

### Флаги

Общие для всех команд:

| Флаг | По умолчанию | Что делает |
| --- | --- | --- |
| `--config` | `sources.yaml` | путь к списку подписок |
| `--workdir` | `out` | рабочий каталог |

По командам:

| Команда | Флаг | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `fetch` | `--refresh` | `false` | скачать заново, даже если файл в `raw/` есть |
| `fetch` | `--attempts` | `3` | попыток на источник: серверы подписок рвут TLS через раз |
| `parse` | `--source` | все | разобрать только один источник по `id` |
| `ping` | `--concurrency` | `200` | параллельных диалогов |
| `ping` | `--timeout` | `2s` | таймаут диала |
| `probe` | `--core` | `mihomo` | путь к бинарнику ядра |
| `probe` | `--url` | `https://www.gstatic.com/generate_204` | URL для проверки |
| `probe` | `--timeout` | `5s` | таймаут на узел |
| `probe` | `--concurrency` | `16` | параллельных проверок |
| `export` | `--target` | `all` | `merged`, `sorted` или `all`; принимает список через запятую |
| `export` | `--keep-pools` | `1` | узлов на один `server:port` в `sorted.yaml`; `0` — без дедупа |

## Статусы узла и пулы

Проба различает не «жив/мёртв», а четыре исхода по коду ответа:

| статус | когда | в `sorted.yaml` |
| --- | --- | --- |
| `alive` | 2xx | попадает |
| `throttled` | 429 | нет |
| `forbidden` | 403 | нет |
| `dead` | обрыв, таймаут | нет |

Ключ пула — `server:port`. Если сервис считает лимит на выходной адрес,
узлы одного пула делят квоту и в профиле дублируются зря: `export`
оставляет `--keep-pools` лучших по задержке, а пул, где хоть один узел
ответил 429 или 403, выбрасывается целиком.

`all` принимает флаги своих шагов и раздаёт их по назначению — можно писать
`proxprobe all --concurrency 24 --refresh`.

## Подписки

`sources.yaml`:

```yaml
sources:
  - id: goida
    url: https://gitlab.com/avencores/goida-vpn-configs/-/raw/main/githubmirror/25.txt
```

Поля записи:

| Поле | Обязательно | Что делает |
| --- | --- | --- |
| `id` | да | имя источника; им же называются файлы в `raw/` и `nodes/` |
| `url` | да | адрес подписки |
| `ua` | нет | `User-Agent`; от него зависит, какой формат вернёт сервер |
| `headers` | нет | дополнительные заголовки |
| `insecure` | нет | не проверять TLS-сертификат |

`insecure` нужен не для экзотики: часть серверов отдаёт неполную цепочку
сертификатов, и обычный запрос падает на `unable to get local issuer certificate`.

## Как устроено

```
cmd/proxprobe/       разбор аргументов и подкоманды
internal/detect/     определение формата по содержимому
internal/parse/      парсеры: links, clash, xray, singbox
internal/model/      узел (Node) и его идентичность (ComputeID)
internal/merge/      слияние источников, отчёт о дубликатах
internal/fetch/      скачивание с учётом UA, заголовков и insecure
internal/probe/      TCP-диал, проверка через ядро, совместимость с mihomo
internal/emit/       выгрузка в Clash YAML
internal/sources/    чтение sources.yaml
internal/testdata/   фикстуры всех пяти форматов
```

Рабочий каталог по шагам (`--workdir`, по умолчанию `out`). Всё лежит по
подкаталогам — ни одного файла в корне рабочего каталога:

```
<workdir>/raw/<id>.raw              скачанное как есть
<workdir>/raw/<id>.raw.meta.json    параметры запроса, которым оно получено
<workdir>/nodes/<id>.jsonl          разобранные узлы по источникам
<workdir>/probe/merged.jsonl        после слияния
<workdir>/probe/tcp.jsonl           после TCP-проверки
<workdir>/probe/http.jsonl          после проверки через ядро
<workdir>/probe/skip.log            строки, которые не удалось разобрать
<workdir>/clash/merged.yaml         все узлы
<workdir>/clash/sorted.yaml         живые, по возрастанию задержки
```

Имена артефактов живут в одном месте — `internal/layout/layout.go`, — потому
что шаги читают файлы друг друга. Каждый шаг создаёт свой каталог сам:
`export` можно запустить сразу после `merge`, не собирая `probe/` вручную.

Всё промежуточное — JSONL, поэтому любой шаг можно посмотреть глазами или
скормить `jq`, не перезапуская конвейер. `probe` и `export` читают
`merged.jsonl`, а не вывод предыдущего шага, так что порядок вызовов между
ними не важен.

## Замечания по проверке

**Почему через ядро, а не REST-API ядра.** Штатный `/proxies/{name}/delay`
непригоден, если на машине работает другой прокси-клиент (например FlClash):
он перехватывает DNS и отдаёт fake-IP из `198.18.0.0/16`, из-за чего
проверка врёт. `proxprobe` вместо этого поднимает своё ядро и ходит через
его mixed-port обычным SOCKS5-запросом.

**Почему `mode: rule`, а не `mode: global`.** `global` без `proxy-groups`
бесполезен: ядро подставляет встроенный селектор `GLOBAL` с `now=DIRECT`, и
весь проверочный трафик уходит напрямую. Тогда живость не проверяется вовсе
— мёртвый узел `0.0.0.0:1` отвечал 2xx, а RTT мерил канал хоста; в логе это
видно как `using GLOBAL` вместо `dial PROBE`.

При `mode: rule` с `MATCH,DIRECT` получается та же ошибка, но тише: запрос
уходит мимо узла, и по логам видно `match Match using DIRECT`. Поэтому
селектор создаётся явно — группа `PROBE` наполняется только узлами текущего
батча, — а перед каждым замером проба переключает её на проверяемый узел
(`PUT /proxies/PROBE`). Переключение и запрос сериализованы мьютексом: иначе
соседний поток успевает сменить узел между `PUT` и началом TLS, и замер
приписывается чужому серверу.

**Почему фильтр по совместимости.** Один неподдерживаемый узел (например
`chacha20-poly1305` в sing-box-нотации) валит **весь** конфиг ядра, а не
только себя. Перед запуском узлы проверяются на совместимость с mihomo, а
шифры приводятся к его именам.

**Имена узлов уникализируются** и в конфиге ядра, и при выгрузке: ядро
отказывается стартовать на двух узлах с одинаковым именем, а в подписках
дубли имён — обычное дело.

## Ограничения

- Проверяется доступность и факт прохода запроса, но не скорость и не
  стабильность: один запрос на узел.
- `clash/sorted.yaml` сортируется по задержке одного замера — при повторном
  прогоне порядок может отличаться.
- Формат угадывается по содержимому; нестандартная обёртка может не
  распознаться. Такие строки попадают в `skip.log`, а не молча теряются.
