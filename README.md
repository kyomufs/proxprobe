# proxprobe

Один бинарник и одна команда: берёт список подписок, скачивает их, разбирает
что пришло, выкидывает дубликаты, проверяет узлы и кладёт рядом готовый профиль
и отчёт о том, почему в нём столько узлов, сколько есть.

```
sources.yaml  ──►  proxprobe  ──►  sub.yaml    профиль для mihomo/Clash
                                   report.txt  что скачалось, что отсеялось и почему
```

## Сборка

```sh
CGO_ENABLED=0 go build ./cmd/proxprobe
```

CGO выключен намеренно: в NixOS нет `gcc`, а бинарник всё равно статический.
В системе собирается из `pkgs/proxprobe/package.nix` в
[nixos-config](https://github.com/kyomufs/nixos-config); версия подставляется
линкером через `-X main.version`.

## Использование

```sh
proxprobe                                  # конфиг и каталог вывода по умолчанию
proxprobe --check=http                     # без TCP-этапа
proxprobe --dedupe=host                    # один узел на адрес сервера
proxprobe --config ./sources.yaml --out .  # локальный прогон
proxprobe --version
```

| Флаг | По умолчанию | Что делает |
| --- | --- | --- |
| `--config` | `$XDG_CONFIG_HOME/proxprobe/sources.yaml` | список подписок |
| `--out` | `$XDG_DATA_HOME/proxprobe` | каталог для `sub.yaml` и `report.txt` |
| `--check` | `tcp,http` | проверки через запятую: `none`, `tcp`, `http` |
| `--dedupe` | `strict` | что считать дубликатом: `strict`, `host`, `none` |
| `--core` | `mihomo` | бинарь ядра (нужен только для `http`) |
| `--jobs` | `16` | сколько узлов HTTP-проверка проверяет одновременно |
| `--dump-raw` | — | сохранить тела подписок в каталог, единственный отладочный артефакт |

Порядок проверок фиксирован: `tcp` всегда до `http`, `none` — только один.
Неизвестная проверка — ошибка запуска, а не молчаливое «пропустим».

### Дедупликация

Подписки пересекаются: один сервер приходит из нескольких источников, часто
десятком записей с разными SNI, портами или UUID. Насколько агрессивно это
схлопывать — флаг `--dedupe`:

| Режим | Ключ | Что схлопывает |
| --- | --- | --- |
| `strict` | протокол + адрес + порт + креденшл + транспорт + reality-отпечаток | только настоящие дубликаты |
| `host` | адрес сервера | зеркала одного пула: разные порты и креденшлы одного адреса |
| `none` | — | ничего, в профиль идут все записи подписок |

Схлопнутые записи не теряются бесследно: узел хранит список источников, из
которых пришёл, а `report.txt` печатает строку `dedupe <режим>` и счётчики
`duplicates`. При конфликте остаётся более заполненная запись — обычно это
Clash-представление с явными reality-полями.

Каталог вывода создаётся сам; файлы пишутся через `.tmp` и `rename`, так что
оборванный прогон не оставляет полуфайл.

### Коды возврата

| Код | Когда | Что с файлами |
| --- | --- | --- |
| `0` | подписка записана, хотя бы один узел прошёл | оба файла обновлены |
| `1` | живых узлов нет или все источники упали | `sub.yaml` не тронут, `report.txt` обновлён |
| `2` | ошибка запуска: конфиг, флаги, ядро | ничего не пишется |

`sub.yaml` не перезаписывается пустым: старый рабочий профиль лучше нового
пустого. Отчёт при этом обновляется всегда, иначе неудачный прогон нечем
объяснить.

## sources.yaml

```yaml
sources:
  - url: https://example.com/sub
  - url: https://example.com/other
    ua: v2rayNG/1.9.16
    insecure: true
```

| Поле | Обязательно | Что делает |
| --- | --- | --- |
| `url` | да | адрес подписки, только `http`/`https` с хостом |
| `ua` | нет | `User-Agent`, по умолчанию `v2rayNG/1.9.16` |
| `insecure` | нет | не проверять TLS-сертификат |

Имя источника — хост без `www.`; оно же в отчёте. Одинаковые `url`
схлопываются: один сервер не скачивается дважды.

`insecure` нужен не для экзотики: часть серверов отдаёт неполную цепочку
сертификатов, и обычный запрос падает на `unable to get local issuer
certificate`.

## Что читается

Формат определяется **по содержимому**, а не по URL: один и тот же адрес отдаёт
разное в зависимости от `User-Agent`, а расширения у подписок нет.

- списки ссылок: `vless://`, `vmess://`, `ss://`, `trojan://`, `hysteria2://`;
- base64 от такого списка;
- Clash/mihomo YAML;
- Xray JSON: одиночный конфиг и пачка (`data:` с массивом конфигов);
- sing-box JSON.

На выходе только Clash/mihomo: остальные парсеры существуют потому, что
источники в этих форматах приходят.

## Что попадает в sub.yaml

- `proxies` — только узлы, прошедшие проверки, по возрастанию задержки.
- `proxy-groups` — `PROXY` (`select`: `AUTO` и все узлы) и `AUTO`
  (`url-test`, интервал 300 с, допуск 50 мс, `https://www.gstatic.com/generate_204`).
- `rules` — `MATCH,PROXY`.

Больше ничего: ни `mixed-port`, ни `mode`, ни `dns` — это дело клиента, а не
подписки.

Дубликаты схлопываются по `(тип, сервер, порт, учётка, транспорт, ключ reality)`.
Имя в ключ не входит: один сервер под десятью названиями — один узел. Имена
уникализируются (` #2`, ` #3`), потому что mihomo не стартует на повторах, а
имена групп `PROXY` и `AUTO` заняты заранее — иначе получится цикл в группе и
ядро отвергнет конфиг целиком.

## Как проверяется

**TCP.** 200 параллельных диалогов, 2 с на узел, имена резолвятся через
`1.1.1.1` и `8.8.8.8`, диал идёт по полученному IP. Ответ из `198.18.0.0/15`
считается ошибкой резолва, а не живым портом.

**HTTP.** Поднимается своё ядро mihomo (порты 17890/19090, `mode: rule`,
`rules: [MATCH,DIRECT]`), узлы грузятся пачками по 500, задержка снимается
`GET /proxies/{name}/delay`. Неподдерживаемый узел валит конфиг целиком, поэтому
перед запуском узлы фильтруются по совместимости с ядром, а шифры приводятся к
его именам.

**Про TUN на машине.** Если включён клиент с fake-IP (FlClash и подобные), он
принимает TCP локально за микросекунды при любом узле: TCP-этап под ним
показывает «жив» всему подряд. Поэтому `proxprobe` это распознаёт (ответ
системного резолвера из `198.18.0.0/15`), пропускает TCP и пишет об этом в
отчёт и stderr. HTTP-этап остаётся осмысленным, но его цифры включают путь
через этот TUN — в отчёте стоит `host-tun yes`.

## Как устроено

```
cmd/proxprobe/       флаги, конвейер, коды возврата
internal/sources/    чтение sources.yaml
internal/fetch/      скачивание с повторами, UA и лимитом размера
internal/detect/     определение формата по содержимому
internal/parse/      парсеры: links, clash, xray, singbox
internal/model/      узел (Node) и его идентичность (ComputeID)
internal/merge/      слияние источников и счётчики дубликатов
internal/probe/      TCP-диал, проверка через ядро, совместимость с mihomo
internal/emit/       sub.yaml и report.txt
internal/testdata/   фикстуры всех форматов
```

## Ограничения

- Проверяется доступность и факт прохода запроса, но не скорость и не
  стабильность: один запрос на узел.
- Порядок в `sub.yaml` — по одному замеру, при повторном прогоне он может
  отличаться.
- Нестандартная обёртка подписки может не распознаться: такие строки попадают
  в `skipped` и в отчёт, а не теряются молча.
- Кэша нет: каждый прогон скачивает источники заново.
